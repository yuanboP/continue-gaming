# Codex 实测：实时执行工作流

历史巡检线 awake-v1 确认序列的五组对照中，标准组 **0/5 通过**，完整工作流组 **5/5 通过**。这里保留该历史版本的原始公开证据，当前统一命名任务包另行提供。

模型请求配置为 `gpt-6-astra / medium`，原生 Codex CLI `0.157.0`，每次 900 秒预算。标准组保留完整 shell、编程、后台定时、图像处理和同模型子调用权限；第二组标准解法实际使用了四路并发视觉调用。

## 五组实测结果

180 秒内检查 24 张真实 PCB query 照片，与独立正常参考比较。通过要求为缺陷剔除 ≥11/12、正常误剔 ≤1/12、空动作 ≤2、碰撞 0，并提供完整签名记录。

## 执行工作流带来的收益

工作流把视觉判断组织为提前采图、四路单件短上下文调用、开发时延校准、模型给出具体动作时间、独立队列执行及回执检查，并处理采图与动作的资源冲突。

五组共 120 个正式判断，57 次实际动作可逐项关联模型输出、入队、执行和签名回执，实际动作无过期。标准组第 1、4 对的最终视觉分类全部正确，工作流进一步解决了“看懂之后及时执行”的实际难点。

含开发练习和子调用的已知 token 为：标准组 **8,909,019**，工作流组 **7,151,851**，本序列减少约 **19.7%**。缓存包含于输入，统计不重复相加；逐线程补账随证据保留。

## 实验范围与方法

这五对使用同一批 24 张图片、两个 SKU，改变出现顺序与时序；结论对应这一历史确认序列。两组匹配 900 秒时间上限，报告实际用量。比较对象是包含并发、提示、上下文、校准及执行方式的完整工作流。

CLI 的型号与 effort 记录为请求配置；方法子调用另有 app-server 实际型号元数据。这里的用量来自保留账本。工作流提供可复用的观察—判断—调度—执行结构，供其他实时任务适配和评估。
